# 上界 と 削る 順（`Bound`）

同時 に 居る 弾 の 上界 と、越えた とき に 絞る 仕組み。取り分（予算）も ここ。

## `SAFETY`（1.3）

式 が 見て いない ぶん の 余裕。大きく する と 上限 を 守る が、`fit` が `wait` を 伸ばして 密度 が 死ぬ。「速くて 避けにくい」と 頼んだ のに スカスカ に なる（実機 で 踏んだ）。

Core で 10 通り 走らせて 校正 した（2026-09-19、`$rank = 1.0`、種 3 通り の 最大、1,800 コマ）。ブラウザ では 背面タブ で コマ が 間引かれて 数 が 取れない。弾数 は 論理値 なので 同じ Core を .NET で 回す。

面 も 実機 に 合わせる（`Stage.portrait` の 480x640、敵 240,80、自機 240,600）。画面外 で 消える 条件（`client/Playfield.fs:432`）を 入れない と、`Vanishing` が 偽 の 弾 が 永久 に 溜まって 別物 を 測る。

| a-spiral-2層-間 | 724 | 418 | 1.73 |
| b-radial-parametrized | 710 | 514 | 1.38 |
| c-aimed-cascade3 | 793 | 682 | 1.16 |
| d-全軸最大 | 672 | 322 | 2.09 |

`SAFETY` を 1.15 まで 下げたら g が 0.89 で 破れた ので、1.3 に 置く。

## `lifeOf`

速い 弾 ほど 短命。180 固定 で 見積もる と 上界 が 3 倍 過大 に なり、`fit` が `wait` を 7 倍 に 伸ばして「速い が スカスカ」な 弾幕 が 出る（実機 で 踏んだ）。

`Breathe` を 見ない と、全軸 最大 で 上界 が 0.85 倍 で 破れた。段 の 子 を 見ずに 親 の 速度 だけ 見て も、実機 の 全軸 最大 で 0.85 倍 に なる。

## `aliveBound`

`$rank = 1.0` で 評価 する。

    (top の発射率 × Σ段 ごと の撒く数 の積 ＋ 層 の発射率) × 寿命

`repeat` の 回数 を 掛けた とき、上界 5,100 万 発 が 出た。

`wait` が 寿命 を 超える と、1 回 の 塊 が 丸ごと 同時 に 生きる。`fit` が wait を 278 倍 に して も、実測 3,351 発 が 減らなかった（予測 539）。

## 削る 順（`fit` / `fitTo`）

1. まず `wait` を 伸ばす（`byWait`）。腕 や 段 を 減らす と 形 と 個性 が 変わる が、これ なら ゆっくり に なる だけ で 済む
2. `wait` で 絞りきれない なら 段 を 1 つ ずつ 落とす。1 回 の 塊 は `wait` で 減らない。全軸 最大 で wait を 278 倍 に して も 同時 3,351 発 の まま だった。上限 を 破る より 段 を 落とす

`fit` の 前 の 実機 の 数：軸 ごと の clamp は「1 本 の 式 が 暴れない」ことしか 保証 しない。

| 仕様 | 同時 |
|---|---|
| Cascade 3 段 | 21,517 発（`MAX_ALIVE` の 24 倍） |
| Cascade 無し | 1,070 発（それでも 破れる） |

実機 で 1,958 -> 662 に 絞った 後 も、腕 18 本 の リング も 3 層 の 重なり も 残った。

## 予算（取り分）

上限 は `fitTo` の 引数。混ぜ と 散らし は 1 面 を 分け合う ので、呼ぶ側 が 取り分 を 渡す。0 以下 は 1 に 倒す（呼ぶ側 の 割り算 で 0 に なりうる）。`generateTo` は 中 で `fit` を 通す。呼ぶ側 に 任せる と 上限 が 守られない 経路 が 生まれる。

## 較正

| 変異 | 赤 に なった 試験 | 備考 |
|---|---|---|
| `Bound.fitTo` が budget を 捨てて MAX_ALIVE を 使う | `取り分 を半分 にすると 同時数 が減る` | |
| `Harmonic.fitTo` が 同上 | `花 も 取り分 で減る` | |
| `Generate.generateTo` が fit を 通さない | `取り分 を半分 にすると 同時数 が減る` | |

空振り した 変異（門 の 形 を 変えた 理由）:

- `aliveBound (fit s) <= MAX_ALIVE` だけ を 見る と 両側 が 一緒 に ずれて 緑 の まま に なる。掛け算 の 項 を 落とす 変異 が 4 本 とも 空振り した。だから 軸 を 1 つ 上げたら 上界 が 増える を 直 に 見る
- `段 の子 は 親 より 遅い` は `subSpeedExpr` の 中身 しか 見ない ので、`lifeOf` が 子 を 数え損ねて も 緑 の まま だった（`for lv in 0 .. -1` の 変異 が 空振り）
- `上界 は いちばん 重い側 の値 になる` を 不等式 で 書いた とき、項 を 1 つ だけ `$rank = 0.5` に した 変異 が 通り抜けた
