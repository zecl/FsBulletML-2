# 内訳を測る（1）回数

> **旧 API 時代の記録。** 数は `BulletRunner.run` / `envOfGlobal` /
> `BulletmlTask` を走らせていた版のもので、いまの `Runner.step` の版とは別物。
> 測った道具（`--count` / `--paired` / `UnitBenchmarks`）は枝 `perf/breakdown`
> にあり、**本流には入れていない** ——`Counters` が Core に計数を埋め込む形で、
> 出荷物に混ぜられなかったため。再現するときはその枝を引くこと。
>
> それでも記録を本流へ移したのは、**数そのものより測り方と外し方に値打ちがある**
> から。「測るときの約束」はここから来ている。

新実装が旧実装より遅い分の内訳を出すための、前半。**ここでは時間を測っていない。
回数だけを数えている。**

時間から内訳を出すには部品を 1 つずつ外して差を見るしかないが、外した版は
計算しているものが変わるので、差が本当にその部品の費用か確かめようがない。
回数は外さずに、しかも正確に採れる。回数で当たりを付けてから時間を測る。

## 採り方

`Counters` に計数を置き、`--count` で 1 回だけ走らせて吐く。

```
dotnet run -c Release --project bench/FsBulletML2.Benchmarks -- --count
```

数える前に同じ台本を 1 回 空回しして、初回だけ走る木の組み立てを外に出してある。
外さないと 60 フレームぶんの数に 1 回きりの費用が混ざる。

**この計数の入った版で時間を測ってはいけない。** 計数そのものが時間を汚す。

## 目盛り合わせ

`stateOfBullet` と `resolversOf` は `BulletRunner.run` の中で必ず隣り合って
1 回ずつ呼ばれるので、**どの台本でも一致していなければ計数が壊れている**。
`move` は弾が 1 つ しか居ないので、60 フレームなら**ちょうど 60**。

5 例すべてで一致し、`move` は 60 だった。

## 読めること

**1. 台本で費用の出どころが逆になる。**

弾の多い台本（5way / 10Way）では、木を歩く量が弾の数に対して極端に少ない。
5way は `run` が 8,910 回 なのに `Sim.run` は 300 回 しかない。産まれた 300 発 の
大半は `<action>` を持たない素の弾で、Tops が空だから木を 1 歩も歩かない。
それでも `envOfGlobal` / `stateOfBullet` / `resolversOf` は毎回 払う。

homing laser は逆で、弾 33 発 に対して `Sim.bind` が 26,999。こちらは木の歩きが本体。

**2. 木の歩きが n^2 で伸びる、という見立ては外れていた。**

`Step.action` は子を 1 つ進めるたびに `List.item idx`（O(idx)）を 2 本 と
`List.mapi`（n セルを作り直す）を呼ぶので、子が n 個の action は
時間も確保も O(n^2) になる形をしている。だが実測の `List.item 辿ったセル` は
5way で 120、10Way で 480 しかない。実物の BulletML の action は子が数個 しか
なく、次数が効くところまで伸びない。**形が O(n^2) であることと、
その台本でそこが効くことは別。**

**3. `envOfGlobal` の半分は捨てている。**

`run` 1 回 につき `stateOfBullet` は 1 回 だが、`envOfGlobal` は 5way / 10Way で
2 回、227 本 で 1.92 倍。増えているぶんはベンチの回し方（フロントエンドと同じ形）
の側にある。

```fsharp
if result.Processed then task.Init(BulletRunner.envOfGlobal bo)
```

`BulletmlTask.Init` はこの `env` を使わない（`BulletRunner.fs` の
`buildRootTops` のコメント）。そして素の弾は Tops が空なので
`finished = endCount >= List.length self.Tops` が `0 >= 0` で毎コマ 真になり、
**生きているあいだ毎コマ この呼び出しを通る**。

`Env` を 1 つ 組むと `Fake.fs` の aim 4 本 を呼び、それぞれが `Math.Atan2` を
1 回 する。5way は `envOfGlobal` 17,820 回 = **atan2 71,280 回**。その半分は
組んだ先で読まれずに捨てられる。

**この 17,820 は、いまの走行の数ではない。** ここは `BulletRun.HasNoScript`
より前の記録で、当時は全部の Env が aim を組んでいた。いまは 96.7% が
skip されるので、Atan2 を回すのは「生」の 296 回 のぶんだけ。
**遅延化の上界をここから掛けないこと**（`--counts` の末尾の但し書き）。

旧実装の同じ場所は `task.Init()` で引数を取らないので、この分は新にしかない。

## ここから先

上の 3 つは**回数の話であって、時間の話ではない**。atan2 71,280 回 が
3,431 us のうち何 us かは、まだ何も言っていない。次は部品を 1 つずつ外して
時間を測り、この回数と突き合わせる（`BREAKDOWN.md`）。
